今天晚间这一组，筛选条件是「创建于 180 天内、近两周仍在 push、star 过 2000」，也就是有半年左右积累、已经跨过原型期的项目。看下来有一条共同的方向性变化值得记：**这批工具正在从「把上下文塞给模型」退回到「先把结构建对，再让模型只做它擅长的那一小步」**。Graphify 用 Tree-sitter 做确定性 AST 抽取，只在文档与图片环节调 LLM；MemPalace 干脆宣称 raw semantic search 无需 API key 就有 96.6% R@5，LLM rerank 只是可选加成；Open Design 则把生成能力整个外包给用户本机已有的 coding agent CLI，自己只做协议层与工件管线。三者都在削减对模型的依赖面积，而不是扩大它——这与年初「什么都交给 agent」的风向是反的。

## 1. [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify) — 96,816 star · 创建于 2026-04-03 · Python · Apache-2.0（README 称与 MIT 双许可）· 最近版本 v0.9.28（7 月 27 日）

**解决的问题**：大型多语言仓库里，「这个模块跟数据库是怎么连上的」这类问题靠 grep 和向量检索都答不好——grep 不懂调用关系，向量检索把结构拍扁成相似度。Graphify 要把代码、文档、SQL schema、配置、PDF 一起变成可查询的图。

**技术架构**：三段式流水线。第一段是**本地 AST 抽取**，Tree-sitter 覆盖 36 种语言语法，抽 `calls` / `imports` / `inherits` / `mixes_in` 边，全程零 LLM 调用、代码不出本机；第二段是**语义增强**，Markdown/HTML/RST、PDF、图片、音视频（faster-whisper 本地转写）走用户配置的模型 API，推断跨文档 `references` 边；第三段用 **Leiden 算法**做社区发现，把图切成子系统，每个簇一次 LLM 调用生成标签。节点除代码实体外还包含从 `# NOTE:` / `# WHY:` / `# HACK:` 注释里抽出的 rationale 节点，边上带 `EXTRACTED` / `INFERRED` / `AMBIGUOUS` 三级置信度标记与来源文件。

**关键实现**：

- **没有 embedding，没有向量库**。存储就是一个扁平邻接表 `graph.json`（默认上限 512 MiB，`GRAPHIFY_MAX_GRAPH_BYTES` 可调），用相对路径，可以直接提交进 git 让全队共享同一份地图。另可导出 graph.html 力导向可视化、GRAPH_REPORT.md（god node、意外连接、建议查询）、以及 GraphML / SVG / Cypher 给 Gephi、Neo4j、FalkorDB。
- **benchmark 打的是记忆系统而非代码搜索**：LOCOMO recall@10（n=300）0.497，对比 mem0 的 0.048、supermemory 的 0.149；LongMemEval-S QA（n=50）76%，与 dense RAG 打平。真正的卖点是第三行——建图的 LLM 成本是 **$0**，纯代码抽取不花一分钱 token。
- **查询走 MCP**：`query_graph`、`get_node`、`get_neighbors`、`shortest_path`、`get_pr_impact`、`triage_prs` 以 stdio server 暴露；也可 `--transport http --api-key $SECRET` 起成团队共享服务。CLI 侧 `graphify query` 返回带逐跳 provenance 的子图，`graphify path A B` 追最短路径。

**演进情况**：v0.9.25 起迁到 Apache-2.0（补上专利授权条款），v0.9.26 到 v0.9.28 连续三天发版，内容全是正确性修复——Python 间接调用不再误连到类定义、增量抽取不再丢掉目标文件不在本批次的跨文件边、Swift computed property 补上节点、macOS 非 ASCII 路径修正。开发主线在 `v8` 分支（1,280 commits），近期加了 PR dashboard、AI triage 排序、共享社区的 PR 冲突检测和 `graphify reflect` 工作记忆反思。企业 SaaS 层在 waitlist 阶段。

**取舍与局限**：JSON 单文件存储换来了可 git 化和零运维，代价是大图查询要全量载入，超过 5000 节点直接跳过 HTML 生成；稠密语料会撞输出 token 上限（`GRAPHIFY_MAX_OUTPUT_TOKENS` 可调）；抽取不完整的图默认拒绝写出，必须显式 `--allow-partial`——这个默认值本身是对的，但会在 CI 里咬人。测试套件只支持大小写敏感文件系统（macOS HFS+ 上 `.f90` 与 `.F90` 会撞）。

**可借鉴**：**置信度分级应当是图的一等公民**。绝大多数代码分析工具把「AST 里明写的调用」和「模型猜出来的关联」混在同一条边里，下游无从区分。Graphify 把 `EXTRACTED` / `INFERRED` / `AMBIGUOUS` 打在边上并保留来源文件，让消费方自己决定信任阈值——任何混合了确定性解析与概率推断的系统都该这么做。另一条是「能用确定性方法做的部分，一律不调模型」，直接体现为 $0 的建图成本。

## 2. [MemPalace/mempalace](https://github.com/MemPalace/mempalace) — 57,783 star · 创建于 2026-04-05 · Python · MIT · 最近版本 3.6.0

**解决的问题**：agent 记忆层普遍靠摘要压缩历史，压完就找不回原话；同时多数方案强绑一个云服务或一个向量库。MemPalace 的立场是**逐字存储 + 本地检索**，不做摘要，不要 API key。

**技术架构**：借记忆宫殿的隐喻做三层索引——**Wing**（人或项目）→ **Room**（主题）→ **Drawer**（原始逐字内容）。这层结构不是装饰，它把检索从「在扁平语料里做相似度」变成「先定域再检索」，是召回率能上去的主要原因。后端可插拔，接口定义在 `mempalace/backends/base.py`：默认 ChromaDB 本地嵌入式，另有 SQLite exact（纯精确匹配）、Milvus、Qdrant、pgvector，全部支持词法检索，各自用一个环境变量切换。另有一套基于 SQLite 的时序知识图谱，实体关系带有效期窗口，支持 add / query / invalidate / timeline。

**关键实现**：

- **检索分层且可停在任一层**：raw semantic search 在 LongMemEval（500 题）上 R@5 = **96.6%**，不需要任何 API key；hybrid v4 加关键词加权、时间邻近加权、偏好模式抽取后，在 450 题 held-out 上升到 **98.4%**；再挂 LLM rerank 可过 **99%**。横向还有 LoCoMo R@10（hybrid v5）88.9%、ConvoMem 250 条 92.9%、MemBench（ACL 2025，8,500 条）R@5 80.3%。
- **嵌入模型二选一**：`embeddinggemma-300m`（多语，约 300 MB）或 `all-MiniLM-L6-v2`（仅英文）。3.3.6 的记录显示换到 embeddinggemma 后跨语言 cosine 从 0.35 跳到 0.88——对中英混杂的会话记忆，这个差距是决定性的。
- **图有生物学味道**：wing 内 hallway、跨 wing tunnel，连接强度按 Hebbian 增强与 Ebbinghaus 衰减演化，而不是静态权重。
- **接入面**：MCP server 暴露 36 个工具；Claude Code 靠 hook 自动落盘会话，Cursor 支持 session-start recall 与压缩前快照，Codex CLI 存 transcript。CLI 是 `init` / `mine` / `search` / `wake-up` / `sweep` 五个动词。

**演进情况**：3.4.0 引入可插拔后端与 CPU/GPU 双 Docker 镜像；3.4.1 补 Cursor 与 Google Antigravity 原生集成，并修掉 embeddinggemma 批量重嵌入时的 OOM；3.5.0 加本地写守护进程（把后台写入串行化到单进程）、MCP 的 HTTP transport（带 DNS-rebinding 防护）、`checkpoint` 与 `delete_by_source` 工具，并把 overview/graph_stats 改成从 SQLite 聚合读取以修大宫殿超时；3.6.0 收口成多后端并发布。方向很清楚：从「能存能搜」走向「多进程安全 + 可运维」。

**取舍与局限**：逐字存储换来可追溯，代价是没有自动摘要，长期磁盘占用与检索规模都要自己管；Claude Code 会话捕获依赖主动 `mine` / `sweep`，README 里那条「不配 hook 则 30 天过期」的提示相当关键，漏配等于静默丢数据。ChromaDB 拖来 grpcio 和 numpy，最小安装并不轻。要 Python 3.9+，另加约 300 MB 模型权重。

**可借鉴**：**把「不用模型就能达到的水位」当成基线公布出来**。96.6% 是零 API key 的数字，rerank 只贡献最后两三个百分点——这种拆分让使用者能自己算清那点增益值不值一次 LLM 调用。做检索系统的都该这么报数，而不是只给一个挂满增强模块的最优值。

## 3. [nexu-io/open-design](https://github.com/nexu-io/open-design) — 81,871 star · 创建于 2026-04-28 · TypeScript · Apache-2.0 · 最近版本 0.13.0

**解决的问题**：设计生成类工具普遍自带模型和云端渲染，用户既换不掉模型也拿不走产物。Open Design 反过来：你机器上已经装了 coding agent，那就把它当成设计引擎，本项目只提供协议、工件管线和预览。

**技术架构**：三层。**前端**是 Next.js 16 + React 18 + TypeScript，负责聊天、文件工作区、沙箱 iframe 预览与设置；**daemon** 是 Node 24 的 Express 服务，用 better-sqlite3 存项目、会话、消息与模板，对外提供 skills / plugins / design-systems 的 REST 接口和 SSE 流式聊天，同时负责 spawn agent CLI 进程、并通过 BYOK proxy 转发模型请求；**agent 层**是真正干活的地方——22+ 种 CLI（Claude Code、Codex、Cursor、Copilot、OpenClaw、Antigravity、Gemini 等）读取 `SKILL.md`（工作流触发与措辞）和 `DESIGN.md`（品牌 token 契约），把工件直接写到磁盘。控制流是 Brief → Plugin → Direction → Design System → Artifact → Handoff → Memory。

**关键实现**：

- **两份 Markdown 就是全部契约**。设计系统是纯 `DESIGN.md`（九段式 schema），skill 是带 `od:` frontmatter（mode / scenario / platform / 依赖的设计系统）的文件夹式 `SKILL.md`。扩展方式简单到粗暴：往 `skills/` 或 `plugins/community/` 丢个文件夹，重启 daemon，picker 里就出现了。当前捆绑 100+ skills、150 套设计系统、261 个官方插件。
- **BYOK proxy 默认防 SSRF**：`POST /api/proxy/{provider}/stream` 接任意 OpenAI 兼容端点，在 daemon 边界直接拦掉 RFC1918、link-local、CGNAT 与云 metadata IP，内网端点必须走 `OD_ALLOWED_INTERNAL_HOSTS` 显式 allowlist。这是把「本地工具有强权限」这件事当威胁模型认真处理的少数项目之一。
- **导出链路是真的**：HTML 单文件内联、PDF 走浏览器打印（deck-aware）、PPTX 由 agent 驱动生成且在 PowerPoint 里可编辑、MP4 走 HyperFrames（HTML + CSS + GSAP → headless Chrome + FFmpeg 确定性渲染）、外加 ZIP 与 Markdown。设备外框放在可复用的 `assets/frames/`，agent 不重画共享框架。
- **自身也是 MCP server**：`od mcp install <agent>` 把 stdio server 写进任意 agent 配置，之后 agent 可直接调 `od search-files`、`od get-file`、`od get-artifact`、`od plugin run`。

**演进情况**：0.13.0（Stay in Flow）主打跨轮次的原生 session resume（Codex、OpenCode、Pi、Open Design Cloud）、可实时切换的模型选择器、以及不离开应用的截图式 PPTX/PDF 导出；同时上线 Open Design Cloud 官方模型服务（20+ 模型、按 token 计费）——开源项目开始长出商业层。Roadmap 排的是 comment-mode 精确编辑、tweaks 面板自动生成、`npx od init`、完整 Plugin SDK，以及 Figma→React/Next/Vue 迁移与「给现有代码库 + DESIGN.md 生成品牌合规 PR」的插件。

**取舍与局限**：把生成外包给 agent CLI，好处是永远不落后于最新模型，坏处是产物质量完全取决于用户装的是哪个 agent，项目自身很难给出稳定的质量下限。已声明未完成的部分不少：comment-mode 精确编辑只部分交付、tweaks 面板 UX 尚未实现、Figma/Pencil 迁移插件处于 alpha、codebase refresh 插件还没发。Linux 只在可选 release 通道出 AppImage。另有个真实的运维坑：macOS 自带 `/usr/bin/od`（octal dump）会遮蔽本项目的 `od` 命令。

**可借鉴**：**把能力边界画在协议上而不是实现上**。项目自己不碰模型、不碰渲染质量，只定义 `SKILL.md` 与 `DESIGN.md` 两份契约、管好进程编排与工件落盘——于是 22 种 agent CLI 都能插进来，新出的 agent 也不需要改代码。做集成层的项目值得抄这个思路：先问「我最少需要定义几份文本契约」，而不是「我要适配多少家厂商」。
